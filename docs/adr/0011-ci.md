# ADR-0011: Continuous integration

- **Status:** Accepted
- **Date:** 2026-10-24
- **Decision:** D15 (spec section 8)
- **Who:** Claude's call

## Context

Determinism and cross-platform behaviour must be checked continuously (G6). The engine repo is public (ADR-0001), so standard runners are free on every target we need. The verification logic must not depend on one CI vendor.

## Decision

GitHub Actions, with the logic in `cargo xtask`. Five native targets plus RISC-V.

- **Only entry point:** `cargo xtask`. Workflows check out the code, restore the cache and call xtask. Every job writes `target/ci/report.json`. Actions are pinned by SHA, `permissions: {}`, `--locked`.
- **Every PR** (target under 15 minutes, measured from rung 1a): fmt and clippy with `-D warnings`, nextest and doctests, cargo-deny, arch-check and the file-size check, replays with the cross-architecture check on Linux x64 and arm64, typos, the RISC-V cross-build with QEMU tests of the core set, and the `wasm32-unknown-unknown` compile check.
- **Native jobs, from rung 1b:** `ubuntu-24.04`, `ubuntu-24.04-arm`, `windows-2025`, `windows-11-arm`, `macos-26`. Intel Mac is compile-checked only. They run on every PR if the repo is public, otherwise on merge and nightly.
- **Nightly:** full matrix with replay equality, benchmarks, the weekly mutation run, a coverage floor, and native RISC-V runs (public repo only).
- **GPU tests without GPUs:** Mesa lavapipe on Linux (exact goldens on x64 only), WARP on Windows, the runner's Metal device on macOS. FLIP thresholds elsewhere.
- **Private game repos:** Linux x64 and arm64 on every PR, macOS on the owner's runner, the full matrix nightly and on tags, a nightly canary against engine `main`.

## Consequences

- Moving to another CI vendor means rewriting only thin workflow files.
- CI computes the `passes` fields (ADR-0010).
- Branch protection on a private repo needs a paid GitHub plan.
- Miri replays, reproducible-build diffs and GPU capture tooling are deferred until after R1, unless a rung needs them.

## Revisit when

At the next wgpu upgrade, switch the pinned Mesa build as the spec says (25.2.7 now; wgpu trunk uses 26.1.3). Otherwise no trigger planned; change only by a new ADR.
